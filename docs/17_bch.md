# BCH error correction

Step 3-3 adds error correction to the NAND channels: a BCH encoder on the program path and a decoder on the read path, between the page buffer and the bus, both in `clk_sys`. Firmware asks for it per command. A Python reference model, `flow/bch/bch.py`, defines the code. It generates the RTL's constants and the test vectors the RTL must match bit for bit. RTL, testbenches, firmware and scripts are at commit `2c9bc8b`, and every result below was measured there.

## The code

| Item | Value |
| --- | --- |
| Code | Binary BCH over GF(2^13), primitive polynomial x^13 + x^4 + x^3 + x + 1 |
| Correction | t = 8 bit errors a codeword: 8 bits per 512 bytes, the usual requirement for SLC parts of this page size |
| Codeword | 529 bytes: 512 of data, 4 of metadata, 13 of parity (104 bits); n = 4,232 bits, shortened from 8,191 |
| Generator | g(x), the product of the minimal polynomials of α, α³, …, α¹⁵: degree 104 |
| Bit order | Bit 7 of a byte first; the first bit has the highest degree, the parity is the last 104 bits |

The constants of the RTL (g(x), the syndrome and Chien search factors, the squaring table, the parity mask) are in `rtl/ecc/bch_pkg.sv`, generated by `python3 flow/bch/bch.py --pkg`; `make -C dv bch` fails if the committed file differs from what the model generates.

## What firmware sees

**An ECC command.** A READ or PROGRAM with CMD_GO.ECC set moves the whole page through the code. CMD_COL and CMD_LEN are not used. In the page buffer the command takes an image of 4,128 bytes at CMD_BUF (0 to 4,064):
- the data, 4,096 bytes, at CMD_BUF;
- the metadata, 4 bytes for each codeword, at CMD_BUF + 4,096.

**The page.** Eight codewords lie one after the other from column 0: codeword c at columns 529c to 529c + 528. Column 4,096, the first spare byte, holds the factory bad-block marker and is left out of them: a program writes FFh there and a read skips it. So codeword 7 runs from column 3,703 to 4,232, 4,233 bytes cross the bus, and columns 4,233 to 4,319 are left alone.

**Erased pages.** The parity is XORed with a fixed mask both ways, the parity of an all-FFh message XOR FFh. An erased codeword, all FFh, is then a valid codeword: an erased page reads as FFh with code 0, and bits flipped in it are corrected like any others. The Linux NAND BCH driver uses the same mask.

| Register | Contents |
| --- | --- |
| CMD_GO.ECC | 1: the whole page through the code (READ or PROGRAM) |
| CPL.CODE | 4: a codeword past correcting (its data is in the buffer as read) |
| CPL_ECC | Of the completion last read from CPL: bits corrected in the page; the most in one codeword; codewords past correcting; codewords erased (at most 8 bits at 0 as read) |
| ECC_COUNT | Bits corrected, codewords past correcting (both wrap) |

A codeword past correcting also sets EVENT.ERR, which raises the channel's error interrupt.

## Encoder

`rtl/ecc/bch_enc.sv` keeps the 104-bit remainder of m(x) x^104 by g(x) as a linear feedback shift register stepped 8 bits a clock. After the 516th message byte its top byte is the first parity byte, and each one taken shifts the next one up. A codeword's first byte restarts it, so a program cut short leaves nothing behind.

## Decoder

`rtl/ecc/bch_dec.sv` takes the received bytes, one a clock at most:
- **Syndromes** (`bch_syn`): the odd ones, S₁, S₃, …, S₁₅, the received polynomial at αʲ by Horner's rule, 8 bits a clock. The even ones follow by squaring, S₂ⱼ = Sⱼ², a linear map.
- **Berlekamp-Massey** (`bch_bm`): inversionless, in the binary form that needs t iterations. Each iteration takes the discrepancy (9 clocks), then updates the locator and the correction term from the top coefficient down, so that every old value is read before it is overwritten (9 clocks). Two GF(2^13) multipliers; 144 clocks in all.
- **Chien search** (`bch_chien`): eight bit positions a clock, 529 clocks for the codeword. Each clock gives the error bits of one byte.
- **Verdict.** A codeword is correctable when the locator's degree, the number of errors Berlekamp-Massey counted and the roots the search found agree and are at most 8. Until then its corrections, at most 8 bytes, wait in a buffer; a codeword past correcting gets none.

A codeword whose syndromes are all 0 is done the clock after its last byte. Any other is decoded while the next one streams in, and its result comes about 700 clocks after its last byte: 145 for Berlekamp-Massey, 529 for the search, then its corrections.

**In the channel.** The data mover feeds the decoder every codeword byte and writes the message bytes into the page buffer as they arrive. A correction is then a read-modify-write of one byte: the word is read, the bits flipped and the one byte written back, with the data mover's own writes first. A read completes when the eighth codeword's corrections are in the buffer.

## Design decisions

- **Codewords one after the other, parity with each.** With the parity of all codewords at the end of the page, eight decodes would follow the last byte. Laid out one after the other, each codeword is decoded while the next one arrives, and a read completes about one decode after its last byte.
- **The marker column left out.** Column 4,096 would fall inside codeword 7. Leaving it out keeps the factory marker readable as FFh on every good block, and costs one byte; a swap of the marker with another byte, which some controllers use, needs more logic on both paths.
- **Erased pages as valid codewords** (the parity mask), so that firmware reads unwritten pages through the code like written ones.
- **Corrections in the page buffer.** The decoder hands out byte positions and bit masks; the channel applies them to the bytes already written, so no second buffer holds a codeword while it is decoded.
- **One decoder at a time.** A codeword's decode, at most about 700 clocks, is shorter than the 1,058 clocks the next one takes to cross the bus at the fastest setting. The decoder holds the next codeword's first byte back until it has taken the previous syndromes, but at the bus timings of these tests it never has to.
- **The model generates the constants.** g(x) and the Galois-field factors come from the Python model, so the RTL and the reference cannot drift apart.

## Python reference model

`flow/bch/bch.py` has the code twice:
- the textbook form: Horner's rule for the syndromes, Berlekamp-Massey with inversions, a Chien search a bit at a time;
- the form the hardware uses: inversionless binary Berlekamp-Massey and a Chien search 8 bits a clock, with the same verdict.

Its self-check (`--self`) corrects every codeword with up to 8 errors, checks that both forms agree, and counts what happens past 8. It writes the vectors for `tb_bch` (`--vectors`).

## Tests

### `tb_bch`

`make -C dv bch` checks the codec on its own against the Python model:
- `rtl/ecc/bch_pkg.sv` must be what the model generates, and the model's self-check must pass;
- for each of three seeds the model writes 600 vectors: a message, its parity, the codeword as received with 0 to 11 bit errors, and what the hardware form decodes it to. Directed vectors come first:
  - no error, an all-0 and an all-FFh message;
  - an error in the first bit sent and in the last parity bit;
  - 8 errors in one byte, across two bytes, only in the parity, only in the message, one in each of 8 bytes;
  - 9 errors, and an erased codeword;
  - 3 to 10 errors whose locators sum to 0, so that S₁ = 0 and Berlekamp-Massey takes its x²τ step first;
- the encoder must give every message's parity, also right after a codeword abandoned partway, as a program cut short leaves one;
- the decoder takes every codeword with gaps in the input (seed 1), back to back (seed 2), or with long gaps and corrections held back 90% of the clocks (seed 3). Its result, its corrections and the message after them must be the model's, and a codeword past correcting must get no corrections. Each result must come within 4,000 clocks of the codeword's last byte.

### `tb_nand`

Three tests join the seventeen of steps 3-1 and 3-2. Each checks the channel as firmware uses it, and the model's array and flip log:

| Test | What it covers |
| --- | --- |
| `ecc` | ECC programs and reads without errors. The model's array must hold the layout, with the parity computed by a reference in the testbench a bit at a time, FFh at column 4,096 and the columns past 4,232 untouched. Images at buffer offset 0, 3, 1,001 and the highest, 4,064, with guard bytes around them; a program and a read queued back to back; an erased page read as FFh with every codeword erased; ECC_COUNT still 0 |
| `eccerr` | Windows of exactly 1 to 8 errors in the codewords, then 8 in every one; 9 in codeword 3 (code 4, EVENT.ERR, the error interrupt, the other codewords corrected); random rates of 10⁻³; erased pages with flipped bits; a bit of the marker column at 0 (no codeword affected); ECC_COUNT |
| `eccrand` | 50 random ECC commands on four blocks: programs of the next page, reads of any page programmed, at random buffer offsets, timing settings and bit error rates from 0 to 2 × 10⁻³ |

- **Every ECC read is checked codeword by codeword** against the model's flip log: a codeword with up to 8 flips must come back as programmed, with its flips counted; one with more must be past correcting, its bytes as read; one with at most 8 bits at 0 as read must be marked erased. CPL.CODE and CPL_ECC must agree.
- **Coverage.** 19 new covergroup bins, 85 in all: errors per codeword by count (0 to 8, past 8), each kind of ECC command and result, unaligned offsets, queued commands, 8 errors in every codeword, the marker column.

### Mutation checks

- **The codec** (`make -C dv bch-mut`): 17 planted bugs:
  - encoder: bit 0 of a byte first, no restart at a codeword's first byte, parity taken a bit off;
  - syndromes: carried into the next codeword, all computed at α;
  - Berlekamp-Massey: the swap one iteration late, τ times x instead of x², γ never updated, S₄ taken as S₂, the error count one short;
  - Chien search: started at the wrong position, bits of a byte reversed, stopped a byte early;
  - decoder: roots left out of the verdict, corrections given for parity bytes, a codeword started before the last one's syndromes are taken, corrections dropped under back-pressure.
- **The channel** (`make -C dv nand-mut`): the 18 of step 3-1 and 10 in the ECC path:
  - no column left out for the marker;
  - metadata at the wrong offset;
  - parity without the mask, programmed or read;
  - a correction applied to the codeword streaming in;
  - a read completed before the last codeword's result;
  - a codeword past correcting not in the code;
  - erased codewords not reported;
  - corrected bits not counted;
  - the metadata word not written when its bytes end.

### SoC: `nand_ecc`

`fw/tests/nand_ecc.c` uses the code from firmware. `tb_soc` gives NAND0 raw bit errors at 500 per million bits and its block 6 at the rated endurance, ten times that rate. The firmware:
- programs four pages of block 5 with ECC from an image the CPU writes into the page buffer, with the row and the codeword number as metadata;
- reads page 3 without ECC and with it, and compares the clocks;
- reads the four pages with ECC and compares them with their images;
- reads an erased page;
- programs and reads a page of the worn block.

The testbench parses what the firmware prints: the bits it saw corrected must be the model's flips in those codewords, and the codewords of the worn page past correcting must be the ones the model flipped more than 8 bits of.

The FIFO count is that of flop inputs reached by FIFO words from the other domain, and grew with the `clk_sys` flops that now depend on them: the decoder's syndromes on the read bytes, the ECC counters on the completion code.

## Found on the way

- **Two blind spots of the codec's testbench, found by the mutation check** before any vector was added for them:
  - **The encoder's restart.** Shifting out the 13 parity bytes leaves the remainder at 0, so an encoder that never restarted at a codeword's first byte still gave every parity in a stream of whole codewords. The encoder now also gets, before every seventh message, part of another one that it must forget.
  - **Berlekamp-Massey's x²τ step.** With random errors the discrepancy is not 0 before the last iteration, so the step that multiplies τ by x² ran only when it no longer mattered, and multiplying by x instead went unseen. Vectors whose error locators sum to 0 make S₁ = 0, so the first discrepancy is 0 and the step counts.
- **A hang.** The Chien search stopped a byte early in one mutant, and the decoder then waited for its last byte for ever. The testbench now fails when a result does not come within 4,000 clocks.

## Limits

- **One code for all pages:** t = 8 is fixed; there is no read retry, soft-decision decoding or stronger code for worn blocks.
- **Whole pages only:** an ECC command reads or programs the whole page; a change of read column has no ECC.
- **One decoder per channel,** at most one codeword decoded at a time.
- **No ECC on the metadata outside the codewords:** columns 4,233 to 4,319 are left alone.
